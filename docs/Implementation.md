# 产品实现｜科研绘图辅助

## 一、问题现状

逐次写提示和逐图调整都难以稳定复用。选图需要研究判断，字体、颜色和导出则可以交给固定程序。因此将判断流程与确定性绘图分别落实为 Skill 规则和 Python 工具。

## 二、实现方式

| 产品决策 | 对应实现 | 可检查证据 |
| --- | --- | --- |
| 先理解数据再选图 | SKILL.md + 选图参考 | [选图规则](../references/chart-selection.md) |
| 将重复样式集中维护 | 共享样式函数与配置 | [paper_style.py](../scripts/paper_style.py)、[配置](../assets/paper.mplstyle) |
| 以统一 CSV 降低首版复杂度 | 通用绘图入口，按参数映射字段 | [plot_csv.py](../scripts/plot_csv.py) |
| 把核对纳入交付 | 输入校验、实际绘图表和来源记录 | [验证记录](Validation.md) |
| 同数据比较再展示 | 原始记录保持一致，分别生成图形 | [对照脚本](../examples/compare.py)、[案例](Examples.md) |

优先复用现有科研脚本能力，将流程、参数与验证组织成 Skill；公开演示使用人工构造数据。具体用户任务输入与输出约定见 [任务合同](../references/task-contract.md)。

## 三、带来的改进

需求能对应到实际文件和验收结果，使用者也可直接运行公开案例。该结构同时保留后续更换样式与新增图形的空间；下一轮先根据失败任务判断是否需要扩大输入范围，见 [复盘](Retrospective.md)。
